# Providence 1.0.1 validation

Providence 1.0.1 includes automatic indexing, file discovery, hybrid retrieval, offline OCR, document previews, Qt Quick/QML navigation, and local scope/privacy controls. This work was originally planned under 1.1.0; the release version is corrected to 1.0.1 while further 1.1.0 work remains open. Tray behavior, login startup, global shortcuts, an installer, signing, and document Q&A are not implemented.

## Retrieval evaluation

Measured locally on Windows 11, Python 3.13.16, CPU inference with two PyTorch threads. The reproducible script is `scripts/benchmark-search.py`: 25 fictional personal files, 200 queries, including English, Filipino, mixed language, exact identifiers and filenames. Both models use the same hybrid retrieval implementation. Qwen uses FP32 CPU inference, instructed queries, last-token pooling and at most 512 tokens per window.

| Metric | MiniLM | Qwen3-Embedding-0.6B |
|---|---:|---:|
| Recall / hit rate at 1 | 86.5% | 92.5% |
| Recall / hit rate at 5 | 91.5% | 96.5% |
| nDCG@10 | 0.9022 | 0.9512 |
| Filipino-only Recall@5 | 66% | 86% |
| Warm single-query encoder p95 | 10.0 ms | 473.4 ms |
| Hybrid lookup p95 with cached query vectors | 7.9 ms | 9.4 ms |

Raw results: [MiniLM](benchmarks/minilm.json), [Qwen](benchmarks/qwen.json). The final Qwen timing run overlapped packaging work, so latency is affected by CPU contention; an earlier run measured 379.8 ms encoder p95. Quality scores were unchanged.

These are smoke-test results, not independent benchmarks or guaranteed accuracy on a personal library. Queries were written alongside the fictional files, so the corpus is not a held-out production dataset. Filename and identifier cases favor the exact branches; they do not measure embedding intelligence in isolation. Every query has a relevant file: no-match detection has not been calibrated, and semantic search can return related files for an unrelated query. Lookup timing excludes encoder time; cold model/graph loading and indexing contention add latency. Hardware tiers, battery impact and representative large-library performance remain unvalidated.

Decision: default new libraries to Qwen when bundled; preserve MiniLM for existing indexes and low-memory users. Switching builds a separate index before activating it, retaining the previous model's library. Qwen improves multilingual recall here at a substantial CPU/memory cost. Its weight file is 1,191,586,416 bytes; FP32 inference expands weight memory beyond the BF16 download size.

Publisher references for broader context: [Qwen embedding model card](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B) and [Qwen reranker model card](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B). The reranker remains optional and is not shipped in this scope. Kimi was considered in the roadmap; its total weight sizes make it unsuitable for this lightweight default. Published leaderboard scores do not substitute for the local evaluation above.

## Scale check

`scripts/benchmark-vectors.py` creates 10,000 artificial files, each with one 384-dimensional passage, in the actual SQLite catalog and HNSW retrieval path. This is a vector/metadata scaling check; it excludes AI encoding, filesystem discovery and parsing.

- SQLite ingestion: 2.53 seconds.
- Initial graph build plus lookup: 2.50 seconds.
- Warm hybrid lookup p95 over 50 calls: 20.5 ms.
- SQLite size: approximately 30 MB.

Real files often have many passages, so these figures do not demonstrate device-wide indexing speed. HNSW graphs are cached in memory and reconstructed from SQLite after changes. Additional memory is required for SQLite records, graph construction, scoped graphs and the embedding model.

## OCR and desktop checks

RapidOCR 3.10.0 bundles PP-OCRv6 small detection/recognition models and an orientation classifier. The three ONNX assets total approximately 31.7 MB, excluding runtime dependencies. Explicit local model paths prevent automatic model fetching. Selection favors self-contained offline Windows packaging; no local comparison against Tesseract was completed.

Tests exercise actual recognition with network connections blocked, scanned PDF page references, PNG text, mixed native/image PDFs, cached results, disabling OCR, cancellation and yielding OCR work to incoming ordinary file changes. Clean printed samples pass; handwriting, photographs with complex lighting and faithful table/layout reconstruction have no accuracy guarantee. OCR is limited to 50 MB files, 500-page PDFs and a 90-second document timeout. Interrupted files requeue and restart their current OCR document; completed documents reuse cached text.

The main desktop shell is Qt Quick/QML, hosted in QQuickWidget. It provides the sidebar, onboarding, browser, search and filters, animated hover/selection, theme transitions and expanding indexing progress. Reduced motion disables animation. PDF/OCR previews and settings/health dialogs remain native Qt widgets sharing existing controllers and services. QML row data changes independently of progress and selection to preserve scrolling. Desktop verification includes paginated virtual delegates, scoped filters, breadcrumbs/history, context actions, theme/motion/layout persistence, stale search handling, search/navigation during indexing, source-change onboarding and live file create/delete notifications. Actual Qt/QML light/dark and minimum-window screenshots are generated by `scripts/preview-ui.py` under `.artifacts/ui-preview/`.

Source validation: **60 passed, 1 skipped**. The skipped Windows symlink test requires permissions unavailable in the test environment. Compile and focused lint checks also pass. These checks validate source behavior; they do not certify every hardware configuration or a particular distributed binary.

The suite was rerun locally after correcting the release version and test-fixture placement: **60 passed, 1 skipped in 31.11 seconds**. A GitHub-hosted run previously failed 42 tests because its fixtures were under AppData/Local/Temp, which discovery deliberately excludes. That condition was reproduced locally. Pytest now defaults to a dedicated disposable workspace directory, `.artifacts/pytest`, without weakening the application's exclusions. The corrected GitHub-hosted run remains pending.

UI checks cover visible settings/health controls, a bounded dropdown with 80 options, file-row geometry at minimum window width, and preview padding. Light/dark, smaller-window, dropdown, settings and health screenshots were inspected. Qt Quick's Basic style provides custom control rendering; file rows reserve scrollbar space. Public [library](images/library-dark.png), [progress](images/search-progress-dark.png), and [clues](images/search-clues-dark.png) screenshots use fictional documents and display paths. The delayed-search screens are staged demonstrations of the interaction, not timing evidence.

Search is now explicitly submitted only. Tests verify no AI search from typing, changing filters, library notifications or an unsubmitted draft after a previous search completes. A simulated long-running search verifies stage percentages, the greater-than-20-second popup threshold, one offer per search session, unknown clue defaults and explicit refinement. Retrieval tests verify remembered folder context reaches the model, folder/type/date constraints affect candidates, file-count limits affect results and cancellation skips unused work. Percentages describe completed stages, not confidence or elapsed-time estimates. Helper messages rotate in shuffled order every five seconds. Active model inference is not forcibly interrupted; canceled work stops at the next stage boundary before an explicitly queued refinement runs. Screenshots include `search-progress-dark.png` and `search-clues-dark.png`. No binaries, release packages or container images were built for these changes.
