# Providence 1.0.2 development validation

Validated on Windows 11 on 11 October 2026. Version 1.0.1 remains the published portable release. No v1.0.2 EXE, ZIP, application Docker image, or GitHub release has been built/published during this work. The separately authorized website Docker container was built and started on localhost:3000.

## Coverage

Source tests cover duplicate content across names/types, same-size different content, hard links, unavailable files, scopes/exclusions, cancellation, incremental visual-index caching, changed/deleted images, model isolation, deletion during encoding, and clearing vectors while preserving originals. UI coverage checks explicit submission and safe closure during work. Parser coverage includes UTF-16, binary rejection, safe HTML text extraction, XLSX rows, PPTX slides, and requeueing formerly unsupported content. Offline checks block socket connections during CLIP encoding and exercise OCR for WebP/TIFF.

Final full suite: **99 passed, 1 skipped in 62.02 seconds**, with offscreen/software Qt and offline Hugging Face/Transformers settings. The skipped test needs Windows symlink-creation privileges unavailable in this environment. The pinned CLIP encoding test also explicitly blocks socket connections. Targeted new tool/parser/model/OCR/search checks passed before the full run.

## Search regression

Failed searches now clear old results and leave the busy state. A completed result discarded because the draft or scope changed also clears the “Searching…” label without submitting another query. Regression tests exercise both paths through the QML bridge.

Completed searches name the submitted query and distinguish word/filename matches from potentially related semantic results. Empty results show “No files found” for that query within the current scope, with a suggestion to adjust filters or description; semantic-only results do not claim that no related file exists. The QML empty area uses the controller's message instead of its discovery placeholder, and semantic rows display “Related.” Status/empty messages render as plain text and wrap within the available space. Empty, semantic-only and mixed-result cases are tested; fictional screenshots were reviewed in light/dark themes and at 1080×640.

Source MiniLM lookup now falls back to the repository's downloaded `build/model` when neither an explicit model directory nor an installed user model is available. A source launch without the environment override previously reproduced “Local model is missing” despite those downloaded assets. After the fix, two searches completed against an isolated copy of an existing index without a model-directory override; original indexed documents and the live index were not modified, and their result names/content are not recorded here. Tests preserve explicit overrides, installed-user-model priority and packaged model paths.

Word retrieval ignores common English filler words when other words are present and gives additional ranking weight to passages containing all remembered words. Spelling fallback checks local filenames and the indexed vocabulary using SQLite's [FTS5 vocabulary module](https://sqlite.org/fts5.html#the_fts5vocab_virtual_table_module): an absent ASCII word of 5–24 letters can use a unique one-edit alternative. Exact words, ambiguous alternatives, identifiers and non-ASCII words are preserved; at most eight absent words are considered. The semantic model still receives the original query. “Similar words” describes a spelling alternative actually observed in a result; complete filename matches retain their filename label. No download, index rebuild, or conversational response is involved.

Mixed letter/digit class and reference codes now constrain retrieval literally: `1CS1`, `1-CS1` and `1-CS-1` are equivalent, while `1CS4` and `1CS10` are different. Required codes can occur in the filename, folder or indexed text. Missing codes return an empty result before model inference. Topic words matched in the filename receive more weight than a folder-only match; combining a code in the filename with attendance text in a passage is also recognized. This is a deterministic search policy for explicit identifiers, not a calibrated relevance threshold. Multiple required codes must be observed together in a path or path/passage combination; codes spread across separate passages without path evidence are not combined.

Result rows and previews explain observed filename, folder and passage matches, spelling fallback and missing topic words. If a required code occurs outside the selected passage, the explanation says it is elsewhere in indexed text. No model-generated reasoning or confidence score is displayed. Preview highlights use matched useful words rather than filler words. Search candidates are restricted to catalog entries, preventing hidden stale index entries from inflating result counts. Five additional tests cover wrong-class exclusion, separator variants, identifier boundaries, scopes/multiple codes, absent-code inference avoidance, catalog removal and visible match evidence. Fictional light/dark/narrow layouts were visually checked. Two attendance queries also passed on an isolated copy of an existing index; private result names and contents are omitted.

`scripts/reproduce-search.py` indexes five fictional documents about student scores, games, accounts and travel. Both MiniLM and Qwen place the student-score document first for “Scores for deliquent” and its correctly spelled variant. This is a synthetic regression smoke test, not verification against a user's private files. The unit test deliberately supplies a misleading semantic order and still requires the combined-word match to rank first.

Semantic retrieval continues to return nearest neighbours, including loosely related documents. No absent-match threshold has been calibrated, and stage percentages do not express match confidence. This change improves word-based ranking; it does not guarantee relevance for every query. Search-specific peak memory was not measured.

The existing 25-document, 200-query synthetic smoke benchmark was rerun with offline model loading. MiniLM Hit@1 changed from 86.5% to 87.5% and Hit@5 from 91.5% to 92%; Qwen remained at 92.5% and 96.5%. These fixtures were authored alongside the application and are not a representative personal-library evaluation. Raw reruns: [MiniLM](benchmarks/search-fix-minilm.json), [Qwen](benchmarks/search-fix-qwen.json). Cached-query hybrid lookup p95 was 29.14 ms and 20.30 ms respectively in these runs; MiniLM overlapped source tests, so timings are observations rather than a controlled speed comparison. End-to-end searches also require model encoding/loading, which those lookup timings exclude.

Code-scope/evidence reruns retained those quality values: [MiniLM](benchmarks/search-codes-minilm.json), [Qwen](benchmarks/search-codes-qwen.json). Cached-query lookup p95 was 32.43 ms and 60.06 ms during concurrent validation work. These timings include evidence construction but exclude query encoding; CPU contention prevents interpreting the difference as a controlled regression measurement. Peak memory for the new code/evidence path remains unmeasured.

## Format and resource limits

- Text/code input: 10 MB, BOM-aware UTF-8/UTF-16 with a Windows-1252 fallback; null-byte binary content is rejected outside UTF-16.
- XLSX: streaming read-only saved values, sheet/row labels, no formula calculation or external-link loading, at most 100,000 rows and 1,000 columns per sheet, two million extracted characters.
- PPTX: text/tables per slide, two million extracted characters; slide numbers are references, not rendered slide previews.
- Office archive expansion: 100 MB. Inline extracted-text preview: 5 MB input. Images: 50 MB and 40 megapixels for visual embeddings, first frame for TIFF.
- Duplicate hashing is chunked and cancellable; reports are snapshots. A file can change after comparison, so review originals before taking action outside Providence.
